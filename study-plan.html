Operating Model

Role Split

You implement and test. I review, question, guide, and explain failures.

Default Hint Policy

Hints first. Full solutions only when you explicitly ask for them.

Study Unit

Read one section, summarize it, build a minimal version, test it, then compare.

Quality Bar

A topic is done when tests prove the core behavior and you can explain the tensor flow.

Per-Topic Loop

  1. Read the relevant book section and repo notebook.
  2. Write a short summary in your own words.
  3. Answer checkpoint questions without looking at the code.
  4. Implement a small, direct version in student/.
  5. Write pytest tests before or alongside the implementation.
  6. Run tests, inspect failures, fix the implementation, and review edge cases.
  7. Compare against the official code only after your version works.

Pytest Curriculum

Status Skill Use It When Example Target
Todo Basic assertions Checking exact values, lengths, types, and simple behavior. assert vocab["hello"] == 0
Todo Fixtures Reusing tiny vocabularies, configs, toy datasets, and seeded models. tiny_gpt_config
Todo Parametrization Testing many edge cases without repeating test functions. empty text, short text, unknown token
Todo Numerical tolerances Testing tensors where exact floating-point equality is wrong. torch.allclose(actual, expected, atol=1e-5)
Todo Randomness control Making dropout, sampling, initialization, and training tests stable. torch.manual_seed(123)
Todo Side-effect tests Checking training changes parameters and evaluation does not. compare parameter clones before and after one step
Todo Smoke tests Running a script or tiny training loop to catch integration failures. pytest -q student/tests/test_ch05_training.py
